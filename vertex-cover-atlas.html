The puzzle in one minute

Every graph has a minimum cover. Not every graph has only one.

A cover is a set of pads that touches every path. The smallest possible size is k, the site's budget. Tap pads below to deploy cats; covered paths light up. Show optimal covers steps through every cover of size k. When there is more than one, the level has a tie.

Reality check

What players actually get today

The three sites with N ≤ 10 were generated with the real makeLevelForDay for 5,000 consecutive day seeds. Bars show the share of days each shape appeared; the drawing count says how many different grid layouts of it shipped. Pick a shape to open it on the bench.

Why so few? makeLevel returns the first candidate that passes its checks, and the small gadget menus hit the same shape first almost every time. At site 3, a 4-cycle, a node and another 4-cycle (budget 4, rated ★★) passes first on 96% of days. Only its drawing and the house art change.

Evaluation

Are ties and shared covers acceptable?

Short answer: yes, with three conditions. Two different graphs having the same cover is irrelevant: the puzzle is the graph, and players never compare answers across levels. Several optimal covers in one graph is also workable, because of how the game already checks a win.

Already fine

Winning and scoring ignore which cover you chose

isCleared only checks that every path is covered, and scoreRun only compares cats used with k. Any optimal cover already scores a perfect run. No SQL or leaderboard change is needed.

Needs a fix

The reveal hint assumes one answer

hintReveal names the next pad of the one stored solution. If the player is building a different optimal cover, that hint pushes them over budget. Re-solving with the player's cats forced in fixes it. The leaf and matching hints are unaffected.

Design choice

Cap the number of ties

A tie is a free choice, and in vertex cover a free choice never costs points. A shape with dozens of optimal covers can be beaten by near-random play, though. A cap of about five keeps the challenge and still gives 781 shapes at N = 10.

Watch the reveal hint go wrong

Two process notes: CLAUDE.md currently says levels must keep a unique optimal cover, and any change to generation changes every day's puzzles and the determinism snapshots. Relaxing the rule is the project owner's decision.

Recommendation

Pick small sites from a catalogue

  • For sites with N ≤ 10, stop growing graphs at random. Precompute the catalogue on this page: a few thousand shapes, each with a grid drawing, k, number of optimal covers and star rating. It fits in a small JSON file.
  • Choose by a seeded day index and skip shapes used recently. Each site then draws from hundreds of shapes and tens of thousands of drawings instead of 3, 8 and 36.
  • This also removes the wall-clock search budget from those sites, which today lets a slow device settle on a different level than a fast one.
  • Keep the current generator for sites 4–7 (14–30 pads), where enumeration is out of reach.

Corrections to the summary file

  • Path 1–2–3–4 does not have a unique cover. The file says {1,3} and {2,4} leave a path uncovered; both are valid covers. P4 has three optimal covers (try it in the first section).
  • Connected labelled graphs at N = 10 is 34,496,488,594,816. That is the value the file's own recurrence gives; the table lists 29,460,703,343,872. Values for N = 3–9 are correct.
  • The formulas, τ = N − α, the cover polynomial, and the planar counts (646 / 5,974 / 71,885 / 1,052,805) all check out.

Method and caveats

  • Reachable means reachable by any sequence of the generator's moves: placing any of its 8 gadgets at an open pad in any of 8 orientations, and adding one extra path between nearby open pads. Every one of 14,982 real levels sampled with N ≤ 10 is in this set.
  • It is an upper bound on what the generator emits: real levels must also hit a target size and star rating, and most reachable shapes are built rarely or never.
  • The maximum-degree-3 ceiling was built independently by vertex augmentation and reproduces the known sequence 2, 6, 10, 29, 64, 194, 531, 1,733.
  • Star ratings use a port of the engine's difficulty(). Optimal covers are counted by brute force over all subsets.
  • Counts for all graphs and planar graphs come from OEIS (A001349, A003094, A001187, A096332).
